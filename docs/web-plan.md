# Web MVP 细化开发计划

总顺序：环境搭建 → 核心算法逻辑封装 → 界面交互开发 → 全流程测试验收。每个模块自检通过后再进入下一个。Electron / Windows 版在 Web MVP 验收后再做。

## 第一阶段：环境搭建
| # | 模块 | 自检标准 |
|---|---|---|
| 1.1 | 工程初始化：Next.js（App Router）+ React 19 + TS + Tailwind 4，分层目录（初版为 Vite，已迁移） | `tsc` 无错误，`next build` 成功 |
| 1.2 | LibRaw WASM 集成：读取 EXIF、内嵌预览、完整解码 16bit RGB | 主流 RAW 样张（CR2/NEF/ARW/RAF/DNG）全部读出 EXIF 和像素 |
| 1.3 | ONNX Runtime Web 集成：本地 WASM、多线程、示例推理 + 4bit 量化算子 | 自检全部 PASS，跨源隔离生效 |
| 1.4 | 基础窗口：导入 → 列表 → 预览 → EXIF → 自检 | Playwright e2e 通过，0 个外部网络请求 |
| 1.5 | 在目标机（M1 8GB，Chrome/Safari）实测 | 记录解码耗时、自检耗时、内存 |

## 第二阶段：核心算法逻辑封装（待第一阶段验收后开始）
- 2.1 解码 Worker 化与流式内存管理（同一时间只保留一张解码图）
- 2.2 降噪模型：Real-ESRGAN 轻量版转 ONNX + 4bit 量化，分块推理，低/中/高三档；WebGPU 优先，WASM 兜底
- 2.3 人脸检测（浏览器端轻量模型）+ 自然磨皮 / 去瑕疵，无参数面板
- 2.4 批处理队列：串行执行、暂停 / 继续 / 取消、失败跳过与失败清单
- 2.5 导出：JPG（质量 0–100）写回 EXIF；DNG 导出方案评估（需自写 DNG/TIFF 写入）

## 已知风险
- WASM 解码与推理慢于原生：24MP 降噪 ≤8 秒需要依赖 WebGPU，需在 M1 上实测
- 浏览器单页内存上限：WASM32 堆最多 4GB，需分块推理并及时释放
- JPG 的 EXIF 读取尚未实现（目前只读尺寸），在 2.5 导出模块一并处理
- 正式部署必须配置 COOP/COEP 响应头，否则退化为单线程
